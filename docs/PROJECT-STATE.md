## Cluster G follow-ups (deferred — surfaced by 2026-04-18 Workspace/View audit vs Obsidian)

Surfaced while investigating a "Split Right leaves empty pane" bug report. A side-by-side comparison of our post-Cluster-G Workspace/View stack against `docs/obsidian-audit/domains/workspace.md §§1-6` and `domains/views.md §1` confirmed the class hierarchy is 1:1 faithful but turned up several gaps. The P0 fix (`duplicateLeaf` semantics + first-render `w->show()` nudge + focus-based active-leaf routing via `QApplication::focusChanged`) landed 2026-04-18 as Cluster G Part 3 — plan at [`superpowers/plans/2026-04-18-cluster-g-part3-split-semantics.md`](superpowers/plans/2026-04-18-cluster-g-part3-split-semantics.md). The items below are the *non-P0* residue to keep on the radar.

1. **Empty-state "New Tab" view (Obsidian's `tD`).** Our `WorkspaceLeaf` has no analogue of Obsidian's empty-pane placeholder with "Create new note" / "Go to file" / "Close" actions. A newly-created leaf with no view is just blank. Audit reference: `domains/views.md §1` (eD/tD/nD trio). Not blocking round-trip compat; improves discoverability. Build alongside the P0 duplicateLeaf work if cheap, otherwise defer.
2. **Unknown-viewType fallback (Obsidian's `nD`).** `WorkspaceLeaf::setViewState(type, ...)` with a type not registered in `ViewRegistry` has undefined UX — Obsidian shows a canned "doesn't look like anything to me" fallback view. Matters once third-party plugins register custom view types and vaults move between installs with mismatched plugin sets. Audit reference: `domains/views.md §1`.
3. **Centralised `Workspace::openLinkText(linktext, source, mode, opts)`.** Obsidian routes all link opens through this single dispatcher; it consults `activeLeaf` and `getLeaf(mode)` and handles sidebar-pinned-leaf "don't steal focus" semantics. Corbomite resolves links ad-hoc inside each view (e.g. `NoteEditorWidget` handles wikilink clicks directly). Missing dispatcher blocks faithful plugin API. Audit reference: `domains/workspace.md §§1, 6`. **R-blocking-partial:** Cluster R's "Open linked view" submenu uses interim dispatch to each plugin's `:open` command (focuses dock panel) until this dispatcher lands; then the submenu upgrades to real leaf-opening without menu changes.
4. **`FileView::receiveSyncState(peer)` linked-pane hook.** Obsidian's group-linked panes sync file via this virtual on `FileView`; we wire `setGroup(id)` + `groupChanged` at the Leaf level but have no base-class hook for file sync across group members. View subclasses would currently have to hand-roll sync, which means they don't. Audit reference: `domains/workspace.md §1`, `domains/views.md §1`.
5. **`lastOpenFiles` sibling key restored on load.** Pre-existing gap carried forward from the Cluster G Task 9 retro (`cluster-retros/cluster-g.md §What surprised`): `Workspace::serialize()` emits `lastOpenFiles` alongside `main`, SessionManager preserves it via unknown-key passthrough on save, but `Workspace::deserialize` is never fed the sibling on load. Not blocking; trivial one-line fix once a consumer cares.
6. **`WorkspaceWindow` popout integration.** Class exists in `libs/core/` (Task 7 was deferred in Cluster G Part 2). Full popout-window lifecycle, separate window state persistence, and cross-window leaf moves are still unbuilt. **R-blocking-partial:** Cluster R ships the "Open in new window" hamburger menu slot as a disabled placeholder; when this follow-up lands the slot goes live without menu changes.
7. **`View.onTabMenu` default implementation.** Close / Close Others / Close After / Close All / Move to New Window are currently MainWindow-wired rather than a `View` base-class virtual with overridable default. Cosmetic until third-party plugin views want to customise the tab context menu.
8. **`ViewRegistry` error paths.** Registering a duplicate viewType, requesting a factory for an unregistered type, and factory-throw-during-construction are all undefined. Audit and harden once `nD` (item 2) lands.
