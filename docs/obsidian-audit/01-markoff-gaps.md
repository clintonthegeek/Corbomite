# Markoff gaps — Pass 1 signal log

Opportunistic bullets noticed while skimming Obsidian's editor/rendering/views domains. Each is a **signal, not a confirmed gap** — Pass 2 must validate scope, priority, and whether Markoff already partly handles it.

Markoff: `/home/clinton/dev/Corbomite/libs/markoff/` (widget), `/home/clinton/dev/Corbomite/libs/markoff-parser/` (parser), `/home/clinton/dev/Corbomite/libs/mmdr/` (Rust Mermaid bridge).

## Editor / live-preview surface

- **Live-preview mode (source-hidden rendering inside editor)** — seen in `obsidian/editor/editorLivePreviewField.js` + `obsidian/editor/markdown/MarkdownView.js`. Obsidian has three modes (source / live-preview / preview); live-preview decorates the editor in-place with rendered widgets while exposing markdown when the cursor enters a block. Markoff's split-region QGraphicsView plan needs to implement the "cursor in block reveals source" semantics.
- **Editor extensions registry** — seen in `obsidian/plugin/Plugin.js` (`registerEditorExtension`). Plugins inject CodeMirror `StateField`/`ViewPlugin`/`Decoration` instances. Markoff has no analogous third-party extension surface yet; Corbomite plugin API will need a translation layer.
- **Bidi / RTL isolates** — seen in `obsidian/rendering/RenderContext.js` (creates `cm-iso` Decoration.marks with `bidiIsolate: Direction.RTL/LTR/auto`). Obsidian handles bidi isolation per-inline. Markoff likely inherits Qt's default bidi; verify mixed-script notes render correctly.
- **Multi-cursor / rectangular selection** — `vendor/codemirror/view/rectangularSelection.js`, `vendor/codemirror/commands/selectNextOccurrence.js`. CodeMirror gives Obsidian these for free. Markoff (on top of QTextDocument/QGraphicsView) does not have multi-cursor; check whether any Corbomite test exercises it.
- **CJK IME input corners** — `obsidian/editor/Editor.js` has `insertText` wrapping IME composition, and the full-width-bracket autocorrect list (`【【` → `[[`, `】】` → `]]`, `！【【` → `![[`). Markoff needs equivalent autocorrect + composition safety.
- **Editor suggesters (`EditorSuggest`)** — `obsidian/editor/EditorSuggest.js`. Plugins drop in autocompleters that trigger on patterns (e.g. `[[` for links, `#` for tags). `src/editor/CompletionPopup` covers the basics for wikilinks/tags but the pluggable trigger API is missing.
- **Command-driven editor operations** — `vendor/codemirror/commands/*` exposes 118 cursor/select/delete/toggle commands. Obsidian's command palette wires to these. Markoff's public command surface is narrower.

## Rendering / preview surface

- **Progressive section-by-section rendering with recycling pool** — seen in `obsidian/editor/markdown/MarkdownPreviewRenderer.js` (`sections`, `asyncSections`, `recycledSections`, `progressiveRender: !0`, `asyncParse: !0`). Obsidian renders large notes section-by-section on a worker. Markoff's `ReadingView` appears to render whole-doc; verify performance on large notes.
- **Heading-collapse (fold a heading and its children in reading view)** — `obsidian/editor/markdown/MarkdownPreviewSection.js` tracks `headingCollapsed` and `level` per section. Not a known Markoff feature.
- **In-document find/replace** — `vendor/codemirror/search/*` + `obsidian/editor/markdown/MarkdownView.js` uses it. Markoff's in-editor find dialog is TBD.
- **Checkbox-click round-trip in preview** — `MarkdownRenderer.prototype.onCheckboxClick` in `obsidian/editor/markdown/MarkdownRenderer.js` rewrites the source `- [ ]` ↔ `- [x]` on checkbox click in preview, keeping source in sync with the rendered DOM. The regex also matches `data-task="?"` so non-`x` custom task markers are preserved.
- **MathJax integration (typeset + finishRenderMath batch)** — `obsidian/rendering/loadMathJax.js` + `renderMath.js` + `finishRenderMath.js`. Obsidian has a batched math-typeset pass. Corbomite has JKQTMathText; whether it has equivalent batching / inline-vs-display distinction is unclear.
- **Mermaid loader with lazy init** — `obsidian/rendering/loadMermaid.js`. Corbomite has `libs/mmdr/` Rust bridge — confirm parity (themes, interactive features, error-pane rendering on invalid diagrams).
- **PDF.js embeds** — `obsidian/rendering/loadPdfJs.js`. Markoff almost certainly lacks PDF embed support today.
- **Prism syntax highlighting (any language)** — `obsidian/rendering/loadPrism.js`. Markoff's code-block highlighting reach needs audit (language list, theme switching).
- **Search-result snippet rendering with highlight spans** — `obsidian/rendering/renderResults.js`. Markoff currently doesn't expose a highlight-spans API for the search panel.
- **Callouts** — `obsidian/settings/SettingTab.js` shows the `callout` DOM structure (`callout`, `callout-title`, `callout-title-inner`, `callout-icon`, `callout-content`) used for `> [!note]` blocks. Markoff-parser handles the syntax; verify the rendered widget chrome matches (foldable, icon-aware, themeable).
- **File-embed inline rendering (`![[Note]]` → preview)** — `obsidian/editor/markdown/MarkdownPreviewView.js` (embed-title + inline-embed + markdown-embed classes). Markoff reading view's handling of nested note embeds is unconfirmed.
- **Hover-link preview popover** — `obsidian/ui/popups/HoverPopover.js` + `obsidian/plugin/Plugin.js` (`registerHoverLinkSource`). Hover any `[[link]]` for 500ms → Markdown preview popup. Markoff/Corbomite need this end-to-end.
- **`htmlToMarkdown` (Turndown)** — `obsidian/rendering/htmlToMarkdown.js`. Used on paste-from-browser. Markoff-parser may not ship a Turndown-equivalent.
- **HTML sanitisation via DOMPurify (`sanitizeHTMLToDom`)** — `obsidian/rendering/sanitizeHTMLToDom.js`. Any plugin-supplied HTML goes through it. Qt equivalent (e.g. whitelist through `QTextDocument::setHtml`) needs to match the allowlist.

## Pass 2 additions — views

- **Three-way-merge on external file modification (`TextFileView.loadFileInternal`).** When the open file changes on disk mid-edit, Obsidian runs `merged = FX(previousLastSaved, currentViewData, freshDiskData)` where `FX` is a diff-match-patch wrapper (`diffMain → patchMake → patchApply`, `_internal.js:461203`), then `setViewData(merged, false)` and shows `msgFileChanged` Notice. The user **keeps their in-progress edits** instead of losing them to a blind reload. Gated on `isPlaintext = true`; BasesView (`isPlaintext = false`) accepts disk verbatim. Corbomite's `NoteEditorWidget` behaviour on external modify is unverified — if it simply reloads from disk, it will clobber unsaved edits. Candidate fix: Markoff-parser-aware three-way merge helper in `libs/markoff/` or `libs/markoff-parser/`; minimum viable path is a text-diff helper in `libs/core/`.
- **Save-failure backup path (`fileManager.storeTextFileBackup`).** On `vault.modify` throw, `TextFileView.save` (a) shows `msgFailToSaveFile` Notice, (b) snapshots the content into the `file-recovery` internal plugin's backup store so the user can recover it. Corbomite has no equivalent backup-on-failure path — a write failure currently surfaces an error but does not preserve the unsaved content. Gap: need a `libs/storage/RecoveryStore` or equivalent.

## Pass 2 additions — workspace

- **Leaf-close undo (`Workspace.undoHistory`, cap 10)** — `pushUndoHistory(leaf, parentId, rootId)` + `workspace:undo-close-pane` (`Mod+Shift+T`). Not bound to editor history; restores the entire view-state + per-leaf back/forward stack. Corbomite has no equivalent close-tab undo.
- **`editorExtensions` is flat-mutable, shared across every `MarkdownView`.** `registerEditorExtension` triggers `updateOptions` reconfiguring every leaf's CM `Compartment`. Markoff's analogous extension registry must use the same "one list, applied to every editor instance" semantics so plugins can't accidentally scope to one leaf.
- **`editor-menu` mid-construction is the primary plugin surface for in-editor right-click actions.** Emitter in `editor/markdown/MarkdownView.js` + `MarkdownPreviewView.js`. Markoff needs `emitEditorMenu(QMenu*, Editor*, MarkdownView*)` with sections `"selection"`, `"action"`, `"open"`, `"view"`, `"info"`, `"system"` populated before emit.
- **`quick-preview(file, unsavedContent)` is per-keystroke debounced cross-pane content sync.** Two panes on same file (one source, one preview) → preview re-renders without waiting for save. Markoff must implement if same-file-two-leaves is supported.
- **`editor:rename-heading` / `workspace:rename-blockid` modals (`pI`/`dI`)** in `editor/markdown/`. Markoff lacks equivalent rename-heading/block-id UX.
- **Hover-previews need 4 pieces wired together:** `registerHoverLinkSource` + `trigger("hover-link", payload)` + Page-Preview internal plugin + `HoverPopover` widget. Markoff is not end-to-end. Minimum Corbomite scope: implement the registry + event so a Markoff widget can emit; the popover widget can come later.

## Pass 2 additions — editor

- **`editorLivePreviewField` is a `StateField<boolean>`, not a tri-state.** Confirms the boolean contract: `true` = live-preview, `false` = source. Reading-mode is a *separate view* (`MarkdownPreviewView`), not a CM state. Markoff's three-mode pivot needs to materialise this boolean on `Markoff::Editor` and expose it via signal+getter so future plugin extensions can mirror `state.field(editorLivePreviewField)`.
- **`editorViewField === editorInfoField` (literal reference identity).** Two public names, one StateField instance. Any future Corbomite plugin shim that exposes both names must preserve this — they update together.
- **CJK autocorrect is just three regexes** (`／(！)?【【$／`, `／】】$／`, `／【【$／`). The full table fits in five lines of code; the third regex is a redundant fallback for the second's no-`！` branch. Port both for behavioural parity. `expandText()` runs first-match-wins on every text-producing input event; Markoff needs an `inputMethodEvent`/`keyPressEvent` hook that mirrors this.
- **`Editor.insertText` appends at end-of-doc, not at cursor** — naming gotcha. Used by IME-composition-end fast-path. A Markoff "insertText" with the same name should mirror the same end-of-doc semantic for compat; "insert at cursor" needs a different name.
- **`EditorSuggest`'s async `getSuggestions` re-checks `editor.hasFocus()` before showing.** Markoff's `CompletionPopup` should mirror this guard so slow lookups don't pop the popup over a different widget after focus moved.
- **First-non-null-`onTrigger`-wins, no priority.** `EditorSuggestManager` (`views/ViewRegistry.js:238–281`) iterates `suggests[]` in insertion order. Built-ins are registered first so plugin overrides of `[[`/`#` are *shadowed* not *prioritised*. A Corbomite `MarkoffSuggestRegistry` should mirror this insertion-order semantic exactly so existing-plugin behaviour ports cleanly.
- **`editorEditorField` / `editorInfoField` may be `null` during view boot** — the StateField initial values are `null`. Plugin extensions reading them in their first `update()` callback get `null`. Markoff's analogue must guarantee init ordering (the per-editor handle is populated *before* the first extension `update`) or document the null-window.
- **Triple-click line-extend selection style** (`K$`, `editorInfoField.js:107–129`). Three rapid clicks anchor a line range; drag extends one line at a time. Markoff uses `QTextCursor` granularity (char/word/block); verify the triple-click-then-drag gesture is implemented end-to-end.
- **`editorEditorField` lets a plugin's CM extension reach back to the wrapping `Editor` instance.** This is the entire reason the public `Editor` API and the public CM-level extension API can coexist. Any Corbomite plugin shim that supports "drop in a custom editor extension" needs an opaque `Markoff::EditorContext` (or per-extension callback param) that exposes the wrapping `Markoff::Editor`. Without it, plugin extensions cannot call `editor.replaceRange(...)` from inside their hook without globals.
- **Plugin-supplied editor extensions go through one flat list applied to every editor.** `Workspace.editorExtensions[]` + `Y$` `Compartment` (`editorInfoField.js:130`) + `MarkdownView.updateOptions()` reconfigure. There is no per-leaf scoping. Markoff's analogous registry must use the same "one list, applied to every `Markoff::Editor` instance" semantics so plugins can't accidentally scope to one tab.
- **`Editor.processLines` is the single atomic-multi-line-edit primitive.** Every list/heading toggle dispatches as one CM transaction, so undo treats them atomically. Markoff's multi-line ops must group similarly; otherwise a single Ctrl+Z could undo half a list-toggle. Also: the special-case anchor nudge for single-cursor `ch === 0` selections (cursor stays at the same absolute character) is a small but real UX win — port it.
- **`EditorSuggest.context` is REPLACED on every trigger, not merged.** Plugin authors who expect `context` to persist across keystrokes are surprised. Document this in any Markoff-shim docs.

## Pass 2 additions — editor-markdown

Confirmed Pass-1 signals (see `domains/editor-markdown.md` §12 for detail):
- Three-mode state machine (`source` raw / `source` live-preview / `preview`) encoded as `{mode, source}`. Cursor-reveal granularity per-**block**, not per-line. Corbomite has two modes only (`NoteEditorWidget::ViewMode {Editing, Reading}`).
- Progressive section render + recycling keyed on **exact HTML-string equality**. Async-parse threshold 10240 bytes. 5 ms / 10-section time budget. Worker returns already-sectioned HTML (`{parseSections: text, options: Ux.globalOptions}` → `{sections: [{html, level, pos}], frontmatter}`).
- Heading-collapse via per-section `headingCollapsed` + `level`; `updateShownSections` hides descendants linearly.
- Checkbox round-trip regex `/<li class="task-list-item( is-checked)?" data-task="(.)" data-line="(\d+)"><input class="task-list-item-checkbox" type="checkbox"( checked)? data-line="(\d+)">/g` preserves custom task markers. `MarkdownRenderer.toggleCheckbox(text, line): {text, char} | null` is a clean pure helper to port.
- `![[Note]]` inline embed: `markdown-embed` + `inline-embed` + `markdown-embed-title` + `markdown-embed-content` classes; per-embed `MarkdownPreviewView`; subpath resolution via `resolveSubpath(cache, subpath) + NT(text, cache, subpath).content`; depth guard `JZ(containerEl)` walks `.internal-embed` ancestors.
- In-document find/replace via `currentMode.showSearch(replace?)`; replace disabled in preview.
- Hover-link event payload `{event, source: "editor"|"preview", hoverParent, targetEl, linktext, sourcePath?}`. `hoverParent` is the view/renderer for popover lifetime binding. Footnote mouseover synthesises `linktext = "#[^" + footnoteId + "]"`.

New Pass-2 signals:
- **Recycle key is HTML-string equality, not AST hash.** Whitespace-only edits force full post-processor re-run on that section (Dataview/MathJax/Mermaid). Consider source-hash or AST-hash keying in Corbomite.
- **Two-level rerender invalidation**: every section with `usesFrontMatter=true` is force-rerendered when frontmatter changes (`JSON.stringify` equality). Source hash AND frontmatter hash.
- **Per-keystroke `quick-preview` emission**: `onInternalDataChange` fires `workspace.onQuickPreview(file, data)` on every debounced edit. A linked preview pane re-renders ~100 times per paragraph typed.
- **Mode-switch triggers save**: `setMode` synchronously `await`s `save()` before leaving `"source"`. Corbomite must match when switching `Editing → Reading` on dirty doc.
- **`MarkdownRenderer.render` without `Component` logs `console.error`** with plugin-stack detection. Corbomite plugin API should require a parent `QObject` for ad-hoc render to prevent event-handler leaks.
- **Heading-collapse affects scroll anchor**: `showSection(target)` walks backwards un-collapsing ancestor-headings so `[[Note#SubHeading]]` nav works even if the parent was collapsed. Corbomite must mirror.
- **Fold-info invalidates on line-count change**: `applyFoldInfo` bails if `fold.lines !== text.lineCount`. External edits silently drop folds. Corbomite's fold persistence should key on block-IDs or source hashes instead of line numbers.
- **`Mod+A` in reading view** shows Notice about `Mod+C`, not select-all; `Mod+C` with empty selection copies entire markdown source.
- **Touch double-tap toggles mode** in preview (300 ms / <30 px travel threshold).
- **`strictLineBreaks` is a GLOBAL parser option** (`Ux.globalOptions.breaks`), not per-view. Toggling in one view affects every open preview.
- **Search-highlight rendering** — absolute-positioned `div` overlays inside a `.search-highlight` container in `sizerEl`, computed from `Range.getClientRects()` of text-walker-located ranges.
- **Scroll is a visual-line FLOAT** (e.g. `42.73`), not pixel offset. Interpolates over per-section heights and `li`-element offsets. Survives reflow/font-zoom. Corbomite must match for `.obsidian/workspace.json` round-trip.
- **Selection preserved across virtualisation**: `updateVirtualDisplay` extends the section window to include any Selection endpoint so virtualisation doesn't tear selection.
- **Worker protocol**: `{parseSections: string, options: Ux.globalOptions}` → `{sections: [{html, level, pos: {start, end}}], frontmatter: unknown}`. Singleton `new Worker("worker.js")` relative to app bundle; lazy-loaded on first big-note parse.
- **`docId = cc(16)` per render** — plugins can key per-render state on it.
- **Print-to-PDF strips `href`** from every `a.internal-link` before printing (prevents `Ctrl+click` during preview). Corbomite's PDF export should do the same.
- **Ctrl+Wheel base-font-zoom** (10–30 px, gated on `baseFontSizeAction` config). 500 ms chord-suppression window via `containerEl` `wheel` listener.
- **Mobile pinch-zoom image viewer** on embedded images (preview mode only).
- **`canShowProperties()` false in raw-source mode only.** Live-preview shows properties editor; raw-source shows YAML inline.

## Pass 2 additions — rendering

Source: `rendering/finishRenderMath.js:5-12`.

## Pass 2 additions — bases

Bases itself is not an editor/rendering surface, but it **consumes** the Markoff/rendering pipeline and **re-uses** primitives that should be shared library code:

- **Two `Value` subclasses are pure markdown/HTML delivery vehicles.** `HTMLValue.renderTo(el) → sanitizeHTMLToDom(data) + app.fixFileLinks(el, "")` and the unnamed `MarkdownValue.renderTo(el) → Zx(Kx(data)) + app.fixFileLinks(el, "")` (source: `bases/TagValue.js:775-803`). Formulas can return these; cells render full rich content. Markoff's HTML sanitiser + markdown-to-DOM pipeline must be reachable from a non-editor context for Bases cells to render. `app.fixFileLinks` (rewrites relative links to resolve against a `sourcePath`) is the bit most likely to be MarkdownView-private today.
- **`ImageValue.renderTo` dispatches on vault-path-shape vs URL-shape** and uses `app.vault.getResourcePath(file)` with the cache-busting `?<mtime>` query string (source: `bases/TagValue.js:755-769`). Desktop `file:///` URLs get rewritten to `Platform.resourcePathPrefix + path`. Image embeds in Bases cells must mirror this exactly for vault-internal attachments to render.
- **`DateValue.renderTo` emits a disabled `<input type="datetime-local">` / `<input type="date">`** (source: `bases/TagValue.js:264-275`) — not plain text. Obsidian theme CSS styles these as pill-shaped date chips. Markoff's date-renderer should emit the same DOM for visual parity.
- **`DurationValue.toString() → moment.duration(...).humanize()`** — "2 months", "a few seconds". Cells render whatever `toString` returns. No `window.moment` in Qt; Corbomite must ship an equivalent humanise helper (KCalendarSystem is close but not identical).
- **Inline-edit cells (`d$` `MetadataPropertyRenderer`) delegate to `metadataTypeManager.getTypeInfo(name, raw).inferred.render(el, value, {app, blur, key, hoverSource, onChange, sourcePath})`** — the type-widget factory (source: `bases/BasesView.js:3029-3043`). This is the rendering-side of the properties-widget registry; for any Corbomite Bases to support spreadsheet-style editing, the Markoff/property-widget layer must expose a Qt equivalent to the JS type-widget contract.
- **`QueryController`-driven progressive rendering** — in Bases, the table widget only renders rows it can see (`QueryController` is out-of-domain, but `BasesView.createRenderer` dispatches per-cell lazily). Markoff's reading-view already does section-recycling (see Pass 1 signals); Bases needs the same pattern at the row level. Confirm both share a common "lazy-render-rows-in-a-scroll-pane" primitive, don't duplicate.

## Pass 2 additions — parsing

The parsing domain has no editor/rendering surface itself, but surfaces two gaps that affect Markoff indirectly:

- **No YAML library in Corbomite.** `Markoff::Document` returns raw frontmatter as a `QString`; it does not parse it. Markoff's Properties panel (`canShowProperties()` in `editor-markdown.md`) requires a parsed frontmatter object at runtime. Without a YAML library (`yaml-cpp` recommended, YAML 1.2, with `nullStr: ""` / `lineWidth: 0` options), properties cannot be displayed or edited in live-preview. Source: `parsing/parseYaml.js`, `parsing/stringifyYaml.js`.
- **`parseLinktext` subpath not extracted in SQLiteIndex.** Corbomite's wikilink regex in `SQLiteIndex.cpp:462–464` does not split off `#subpath`. When a `[[Note#Heading]]` link is stored, only `"Note#Heading"` (or similar) reaches the index target column — the subpath is not stripped. This means scroll-to-subpath on link-click will fail until `parseLinktext` semantics are applied at indexing time. Source: `vault/parseLinktext.js:46369`; consumer `SQLiteIndex.cpp:498`.

## Pass 2 additions — search

The `obsidian/search/` domain does not itself touch Markoff (`N/A` in `domains/search.md` §12), but the audit uncovered matcher/renderer contracts Markoff-adjacent surfaces (Quick Switcher, Command Palette, CompletionPopup, SearchPanel, snippet overlays) must share:

- **`{score, matches: [[s,e],...]}` is the canonical result contract** from `fuzzySearch`/`prepareFuzzySearch`/`prepareSimpleSearch`. Every Obsidian highlight-span renderer (`renderMatches`, `renderResults`, footnote/file/tag/link suggesters, search panel snippets) reads the `matches` offset array. Corbomite's `struct SearchMatch { QString notePath; QString snippet; double score }` (`libs/storage/include/corbomite/storage/SQLiteIndex.h:14-18`) lacks the byte-range array; no Obsidian-compatible highlight spans can be drawn from it. Minimum fix: add `QVector<std::pair<int,int>> matches` to `SearchMatch` and populate from (a) FTS5 `snippet()`/`highlight()` parsed back to offsets, or (b) re-scoring FTS candidates through a ported `fuzzySearch` (preferred for plugin-compat).
- **The two-pass matcher algorithm (word-token → char-fuzzy with CJK per-codepoint tokenisation)** is the reason typing `gmf` matches `getMarkdownFiles`. `QRegularExpression` + `QSortFilterProxyModel` cannot reproduce this ranking. Port `prepareQuery` / `fuzzySearch` / `prepareSimpleSearch` / `sortSearchResults` as free functions callable from Markoff-adjacent consumers without dragging in the SQLite index. Source: `search/prepareQuery.js`, `search/fuzzySearch.js`, `search/sortSearchResults.js`, `_internal.js:83097-83224` (internals `Ty`/`Iy`/`Ly`/`wy`/`xy` + regex classes `Cy`/`ky`/`Ey`).
- **Shared highlight-span renderer chokepoint.** `renderMatches(el, text, matches, offset?)` is called from every Obsidian suggestion-row, snippet-panel, footnote/file/tag/link/command picker (re-exported by `rendering/renderResults.js:5-7`). Corbomite needs `Markoff::renderHighlightedRuns(QTextCursor, QString, const QVector<std::pair<int,int>>&, int offset=0)` as the single primitive every search-ish widget renders through. Duplicates this note from the Pass-2-rendering block above with a stronger justification: losing this chokepoint means SearchPanel, Quick Switcher, Command Palette, and CompletionPopup each ship their own highlight DOM builder and diverge on highlight-class naming.
- **Offset-shift parameter** on `renderResults(el, text, {matches}, offset?)` / `renderMatches(..., offset?)` — lets callers render a pre-existing prefix before the matched text without re-indexing the ranges. Corbomite's shared helper must accept this offset or force every caller to manually rebase ranges.
- **Empty-query semantics** (`{score: 0, matches: []}`) must be preserved so a fresh SuggestModal / Quick Switcher / Command Palette open shows the entire item list, not an empty one.

## Pass 2 additions — ui-bundle (popups + hover-link)

Confirmed + refined from Pass 1:

- **`HoverPopover` default `waitTime` is 300 ms, not 500 ms.** The 500 ms figure in the Pass 1 signal is the **poll interval** of the window-level `elementFromPoint` scan (`nX` in `ui/popups/HoverPopover.js:70`), not the per-popover show delay. Constructor signature `new HoverPopover(parent: Component, targetEl: HTMLElement, waitTime: number = 300, staticPos: {x,y,doc}? = null)` (source: `ui/popups/HoverPopover.js:73`). Corbomite should expose both as user-tunable ("link preview hover delay", default 300 ms; global hit-test poll, default 500 ms).

New Pass-2 signals discovered in this domain:

- **`HoverPopover.staticPos` override for long targets.** `HoverPopover.position()` (`ui/popups/HoverPopover.js:228-236`) anchors to the mouse cursor (not the target rect) when `targetEl.offsetHeight > 300 px`. Avoids the popover landing far off-screen when hovering a paragraph-spanning link. Corbomite's `Corbomite::HoverPopover` must mirror this branch for UX parity on long wrapped links.
- **Child-popover chain via `HoverPopover.childHovers`** (`ui/popups/HoverPopover.js:132-143`). A popover spawned from a link inside an already-open popover is tracked as a "child". The parent's `shouldShow()` stays true while any child is visible, so hover-navigating "Note → [[link inside]] → [[link inside that]]" keeps the whole chain open. Corbomite needs a shared `Corbomite::HoverPopoverRegistry` with ancestor-relationship tracking; a single-instance popover widget is insufficient.
- **`HoverPopover.watchResize(el)` with 10-call cap** (`ui/popups/HoverPopover.js:275-294`). A `ResizeObserver` re-calls `position()` up to 10 times as content loads, then disconnects to prevent thrashing. When an embedded image loads late, this keeps the popover visually anchored. Corbomite port: `QResizeEvent` filter with a `repositionCounter` capped at 10.
- **Pin-to-keep-open via `HoverPopover.setIsFocused(true)`** (`ui/popups/HoverPopover.js:149-151`). Short-circuits `shouldShowSelf()` — popover stays open after `mouseout`. Page-Preview internal plugin sets this when user presses the configured modifier key during hover. Enables "click the link inside the popover to navigate to it". Without this, users cannot interact with preview content. Corbomite must implement.
- **`MomentFormatComponent` live-sample binding.** `setSampleEl(el)` + `updateSample()` (source: `ui/components/BaseComponent.js:509-531`) calls `window.moment().format(inputEl.value || defaultFormat)` and writes the current-time result into `sampleEl`. Daily-Notes settings show a live "what today's filename would be" preview. Corbomite must ship a Moment-compatible format function to power this UX — `QDateTime::toString` uses different token syntax (`yyyy` vs `YYYY`, `d` vs `D`, `AP` vs `A`) and will silently corrupt user-supplied Moment strings.
- **`Notice` container is per-window**, not per-app (`ui/popups/SuggestModal.js:400-401`, `db: WeakMap<Window, HTMLDivElement>`). Popped-out windows each have their own stack. Corbomite's `Notice` widget must respect `QWidget::window()` to avoid cross-window clipping.
- **`Notice` mouse-enter freezes auto-hide, mouse-leave extends by 1 s** (`ui/popups/SuggestModal.js:443-448`). Users reading a long notice never miss it. Trivial but important — Qt's `QToolTip` auto-hides on the first `QEvent::Leave` without this grace window.
- **`Modal.shouldRestoreSelection` covers text selection, not just focus** (`ui/popups/Modal.js:110-135`). On close, the modal restores both `(range, focusEl)` snapshot taken on open — with special-case guard for `CodeMirror .cm-content` (skip restore to avoid racing CM's own focus handling). Qt's `QDialog` close restores focus widget but *not* the active `QTextCursor` position. Corbomite `Corbomite::Modal` must extend `QDialog::closeEvent` to snapshot/restore `QTextCursor::position()` + `QTextCursor::selectionStart()` for the prior focus widget if it is a `QTextEdit`/`QPlainTextEdit`.
- **`setIcon(el, name)` idempotency** (`ui/icons/setIcon.js:5-12`). If first child is already an `<svg>` with class matching `name`, no DOM mutation. Safe to call every paint frame. `QWidget::setIcon(QIcon)` has similar no-op-on-same-icon semantics but Qt's check is on `QIcon` instance identity, not theme-name match — so setting the same Freedesktop theme name twice *will* reconstruct the `QIcon`. Cheap but not free; Corbomite's `setIcon` helper should cache by name.
